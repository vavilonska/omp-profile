# Astra / Sol 工作流说明

> 2026-10-24 规则快照。本文描述当前方案的职责、流程和限制；不包含私有配置或部署资产，不代表当前某个会话的实时模式。范围与脱敏声明见 [分享范围](SHARING.md)，接入方式见 [使用说明](SETUP.md)。

## 1. 目标与基本原则

工作流以完整、高质量完成用户实际目标为首要标准。主控保留对目标、关键假设、一级依赖、重大取舍和最终证据的判断，执行角色自主完成适合委派的探索、实现、排障和验收。

核心原则：

- 正确性优先，兼顾长期维护成本、用户体验（UX）、开发体验（DX）与代理使用体验（AX）。不为抽象完整性增加无关机制。
- 简单任务直接完成；独立且有收益的工作并行。代理数量、测试数量与主控负担都不是优化目标。
- 普通实现选择和必要连带修改在原授权内自主处理。数据、资源、费用、公开操作及明确暂停等边界不能自行扩大。
- 复用现有技术约定、唯一权威状态与有效证据。发现共同根因时修复接缝，不用吞错、假回退或特殊输入绕过问题。
- 全目标完成且证据充分即结束；阶段消息、局部通过或代理结束都不等于整体完成。

## 2. 信息分层与按需加载

工程规则由公共技能维护，主控规则只承载控制职责，角色文件只定义各自边界。维护说明负责配置基线与兼容记录，避免把长历史注入每个任务。

| 层级 | 职责 | 加载方式 |
|---|---|---|
| 主控规则 | 目标裁决、分工、权限、证据判断、表达和入口 | 由宿主加载主控规则 |
| `engineering-workflow` 核心技能 | 公共工程合同与条件路由 | 工程设计、实现、集成或审查时读取；已有完整正文则复用 |
| 核心技能的 `references/` | 特定阶段的操作细则 | 触发对应动作时读取，不预读全部文件 |
| 专项技能 | 前端设计、Android 等领域约束 | 仅在任务涉及该领域时加载 |
| 角色文件 | 职责、权限和结果要求 | 按实际角色加载；不假设子代理继承父对话 |
| 工作流维护说明 | 模型基线、实现接点和历史证据索引 | 更新 OMP、调整模型或提示词、自审工作流时读取 |
| 项目指南与历史 | 当前入口、项目权限、必要环境风险；历史另存 | 项目规则按环境提供，历史按问题定位 |

公共工程技能的五份支持文件：

| 文件 | 触发条件 |
|---|---|
| `references/research.md` | 研究实验、开放方案选择、持续负结果下的路线裁决 |
| `references/execution.md` | 启动命令、子进程、浏览器、设备或长运行 |
| `references/collaboration.md` | 派发、接合、监管、消息、等待、重组或恢复控制状态 |
| `references/runtime-protocols.md` | 模型路由、思考分档、模式切换、历史咨询与结果协议 |
| `references/verification.md` | 选择测试或 runner、验收、审查与发布证据判断 |

对应文件随仓库的 `profile/` 目录提供，保持 OMP agent 目录布局。本文解释规则，实际使用的正文位于 profile 中；维护时避免两者语义漂移。

## 3. 模型模式与思考强度

### 3.1 混合与全 Astra

混合模式以 Astra 主控、Sol 执行为基线；全 Astra 模式将当前工程树切换到 Astra。两种模式使用同一套角色、技能、权限及生命周期，不另建编排平台。

维护说明记录的模型基线如下。实际生效值以运行时为准，不能用本文覆盖用户后续配置。

| 模型角色 | 记录的基线 | 用途 |
|---|---|---|
| `default` | `openai-codex/gpt-6-astra:high` | 主控 |
| `plan` / `slow` | `openai-codex/gpt-6-astra:xhigh` | 显式规划或疑难路由 |
| `task` / `smol` | `openai-codex/gpt-6.1-sol:high` | 混合模式执行基准 |
| `vision` | `openai-codex/gpt-6-astra:medium` | 图像角色 |

搜索、记忆、压缩、图像生成等辅助路由保持各自设置；不随工程模式切换统一改写。advisor 与 prewalk 不默认开启。并发、Fast 和全局思考上限也不因模式或单个任务升档而擅自改变。

### 3.2 模式切换与原位接力

本方案通过本地工作流扩展提供的 `workflow` 接口控制模式，并非任意原生 OMP 安装都具备这些动作。

| 动作 | 含义 |
|---|---|
| `status` | 查看真实模式、模型、思考与服务档位、待应用状态 |
| `astra` | 根据当前真实用户授权，将当前工程树切到 Astra |
| `mixed` | 恢复原工程模型和后来明确选择的配置，不把所有角色写死为 Sol |
| `raise` | 对指定实际子代理请求更高思考档，不改变工作流模式 |

切换由当前真实用户请求授权，历史消息与子代理转述不构成新授权。主控调用实际工具后，区分已应用、待安全点与失败，不只口头宣布。

原位接力保留同一代理、会话、工具结果和所有权，在下一安全模型调用点应用。已在途请求自然结束；登记为 pending 不表示已经换模，也不唤醒已完成或已取消的代理。全 Astra 覆盖嵌套工程子树、eval/workpool 与历史咨询，但不改变其权限。

模式与必要选择沿根会话持久化；恢复时隔离不同根、取消状态及复用的 ID。缺少持久归属的无会话运行不支持全树接力。扩展变更需正常新进程加载，不承诺旧窗口热更新。

Fast 属于服务档位，thinking 属于思考强度，两者独立。Fast 广播沿根服务档位在子代理安全点同步，不覆盖其他提供商或全局设置。请求携带相应字段不证明服务商实际兑现加速。

### 3.3 思考强度选择

| 档位 | 使用依据 |
|---|---|
| `high` | 普通探索、明确合同实现、常规排障和既定验收；当前普通子任务基准 |
| `xhigh` | 存在尚未解决、会改变方案的竞争解释或关键设计取舍，需要具体反例推演 |
| `max` | 有进一步反证或耦合疑难，且有依据表明 xhigh 不足以闭合判断 |

文件多、跨模块、涉及权限或状态机，以及普通失败次数，都不自动构成升档依据。依据写在已有派发说明或 `solutionSpace` 中，不另建打分和逐项审批体系。

普通派发省略 `effort`，保留当前基线与用户后选。原生 `task.effort` 的值为 `lo | med | hi`；在当前 Astra / Sol 及允许上限下，`hi` 对应最高档 max，不能将其当作 xhigh。

需要精确 xhigh 时，先默认派发，取得实际子代理 ID，再由根主控通过 `raise` 指定 `level: xhigh`。首个已在途请求仍可能是 high。省略 level 固定请求 xhigh，重复请求不会自动升到 max；显式 max 需满足相应依据。

实际应用受模型支持档位和原生 ceiling 限制，向下约束，不因缺少 xhigh 向上跳到 max。请求值、pending 与实际应用值分别报告。后续被原生记录的明确人工选择优先；没有事件的同值设置不能被声称已撤销 pending。

普通 task 和 eval 子任务不使用接口未暴露的单次 model 覆盖。历史咨询 `seance` 依实际接口可指定来源会话及模型，但保持只读、不修改原历史，并服从工程树的实际路由。

## 4. 主控与执行角色

| 角色 | 主要职责 | 边界 |
|---|---|---|
| 根主控 | 用户目标、关键假设、一级依赖、共享合同、重大取舍与最终证据判断 | 所有模型可见提示词由根主控判断、起草、修改和审定 |
| 官方 `task` | 明确范围内的探索、模块设计、非提示词实现和普通排障 | 派发明确不再委派，遵守原生阶段限制；不复制或同名覆盖官方角色 |
| `scout` | 陌生代码的只读定位与有界研究 | 不承担代码修改；无执行能力时不承担 CLI 或 eval/archive 调查 |
| `sonic` | 严格机械更新或数据收集 | 不承担需要开放设计判断的工作 |
| `verifier` | 稳定输入的运行验收、真实 CLI/UI、环境诊断与证据交付 | 默认不改生产代码，不再委派 |
| `integrator` | 接合已完成分片、处理范围内修复并统一验证 | 不重做全部实现，不再委派，不无限吸收新增职责 |
| `work-lead` | 复杂局部子图的持续协调与依赖接续 | 不递归建立主管链，不接管整个工程 |
| `reviewer` / `security-reviewer` | 定向只读审查与有证据的缺陷定位 | 不把风格偏好、假想风险或可选增强变成阻断 |
| `seance` | 只读历史咨询 | 不修改来源会话，不从历史继承新权限 |

角色是责任划分，不是固定流水线。小任务可由主控直接完成；已有 integrator 覆盖的有效验证，不再默认派 verifier 重跑。需要独立审查时按实际风险安排。

提示词所有权覆盖系统、角色、技能、工具模板及代码内模型可见指令。子代理可做明确派发的非提示词实现及不改文案的加载验证；发现提示词问题交位置、约束和证据，由主控处理。

## 5. 一次任务的完整推进

### 5.1 明确范围并做必要研究

先区分用户目标、完成标准、硬性权限与可调整的实现选择。工程任务加载公共核心，按实际动作补充细则。读取本次必要源码和直接消费者；陌生范围交 scout 定位，不默认扫全仓或整份历史。

简单明确的任务直接处理；多阶段任务使用待办记录实际交付项。待办和自定文件清单是执行工具，不能变成用户未要求的停工边界。

### 5.2 按真实依赖拆分

主控确定一级依赖和共享接口，分片足够定位即可派发，不先替执行者设计完所有内部步骤。每片交代目标、完成标准、必要入口、权限边界、真实未知、文件写窗口及接续责任。

子代理不被假设继承父对话、主控规则或项目上下文，必要规则与技能入口需显式交接。

独立工作批量并行；有真实依赖的工作等待输入就绪。每个共享文件和实际进程都有明确 owner。代理数不等于工作线程数，唯一重计算 owner 不妨碍无关工程工作并行；并发受实际资源约束，不相乘嵌套上限或凑满槽位。

### 5.3 实现、消息与工作包调整

执行者在边界内自主设计、实现和排障，保护用户并行改动。普通接口接合不逐项请示；改变共同语义、权限或责任转移时，由相关负责人明确接合。

实质进展报告已完成事项、关键证据或阻断、下一可观察节点及需要的决定。普通阶段消息发出后继续；需要负责人裁决时及时递交证据，不等服务退出才汇报。

新模块或生命周期接缝显著扩大工作包时，负责人重新判断分担、协调或接管范围。交接保留已有成果、接口、成功证据、未验项、写窗口释放点与进程 owner，不整体重启、不双写。

### 5.4 等待、插话与恢复

有独立工作先推进。确实阻塞时，只等待本次登记的 job/service，或运行时支持的欠回复直接消息；任意 peer、广播或历史消息不自动取得等待资格。

无对象或对方不可回答时按实际返回原因接续，不忙轮询、不创建占位任务。消息送达不等于批准，阶段汇报不等于终态，子代理终态也不替代实际进程退出。

用户提问、回顾或困惑不自动暂停原任务；真正停令或权限撤回立即按范围执行。恢复时保留控制来源、当前代际与已履行操作，不重复已完成插话，也不因插话完成而结束原目标。

### 5.5 验收、收尾与交付

稳定输入交相应 owner 验收，不等待无关工程全部完成。检查期间保持被读取的实现和依赖稳定；需修复时先收口受影响运行，再补相关证据。

交付包含实际完成内容、关键接口或不变量、运行入口与结果、影响结论的未验项及资源状态。完成后更新受影响说明，临时工具保留至最后消费者结束再清理。清理和记录不扩展成通用运维平台。

## 6. 结果协议

内容是否完整与通过哪个通道返回是两件事。实际接口和 schema 优先，不能只凭角色名称推断。

- 普通文本 task：未启用结构化结果时，最终 assistant 消息就是结果，没有 yield 工具；不能伪造结构化校验成功。
- 结构化角色：角色可显式启用结构化结果，即使全局关闭也不能据此断言无 yield。只使用当前接口实际提供的字段和工具。
- 增量 section：遵循上游单元素协议，一次一个 section 标签，data 直接是该 section 的值；数组 section 一次提交一个元素，不使用本地批次或多标签映射扩展。
- 最终结果：已合法提交完整 sections 时可用无 data 的 result 终结；显式终态 data 必须是符合完整 schema 的全量结果，不与旧 sections 做局部合并。
- 拒绝与失败：被拒绝不算交付；按错误纠正或沿原生失败路径处理，不放宽校验、用占位值覆盖有效结果或另建旁路重试器。
- workpool：遵循自身逐项返回协议，不擅自套用另一通道。

最新交接应自包含全部仍有效范围、证据、未验项与资源状态，不只给相对上一稿的修订摘要。

## 7. 验证与证据判断

必要行为必须运行观察。编译成功、退出码为零、测试数量、schema 通过或代理声称完成，都不能单独证明目标消费者正常。

| 变化类型 | 主要观察对象 |
|---|---|
| CLI / TUI | 实际入口、交互、输出及状态变化 |
| Web 界面 | 真实页面、代表性尺寸、关键操作、截图与焦点等可用性行为 |
| API / 数据协议 | 真实调用方、合法边界、错误、状态转换与最终消费 |
| 跨模块变更 | 生产者到消费者的关键值、身份、版本和准入接缝 |
| 提示词或技能加载 | 实际发现、读取及装配链；与模型长期行为分别判断 |
| 部署或发布 | 同一待交付载荷的共有行为、安装入口和实际运行身份 |

有效证据随交接复用。输入未变、覆盖仍成立时，不因换 owner 或进入新阶段重跑；只补受变更、失败或具体缺口影响的路径。

永久测试保护消费者可见行为、边界、不变量和真实回归，不测试源码镜像、机械转发或 mock 回显。临时真实消费者足够验证的接合，不必建立长期测试框架。用户已报告的失败视为事实，不重跑只为确认其真伪。

明确区分源码 loader、手工装配、默认发现、正式 CLI、安装目录、合成响应与真实 provider。前一种证据不自动证明后一种，更不能推出长期模型遵从、线上 Fast 兑现或业务收益。

独立审查给出位置、触发条件、违反合同、后果与证据；同时报告覆盖和未验项。指定范围无发现不等于全局正确。多个消费者能够推翻同一产物时，共有行为验收收齐后再打包发布；验收通过仍不自动授予发布权限。

## 8. 静默运行、隔离与资源

普通命令、构建、服务及自动化验收默认后台执行，不弹窗、不抢焦点，同时保留日志、错误、取消与真实退出责任。

- Windows 非交互子进程使用有效的无窗口入口或相应进程创建选项；`async`、`pty: false`、重定向及非交互参数本身都不保证隐藏。
- WSL 反向启动 Windows 程序时单独核对互操作入口，不能把 Linux 参数与 Windows 进程选项混用。
- Web 自动化默认独立无头浏览器，不使用用户日常标签或真实 profile。绕过浏览器 relay 不等于已启用无头。
- 只有展示、人工登录、原生窗口、托盘、焦点等验收确有需要时才使用必要界面。静默入口失败不自动授权弹窗或修改系统设置。
- 可能写状态的 CLI 或探针按实际写入面隔离工作目录、配置、会话、缓存和临时数据；查询命令也未必只读。
- 数据隔离不代替资源互斥。共享 CPU/GPU、服务租约或其他受限资源沿既有授权入口，不另建私有门禁绕行。
- 长运行按真实生命周期监管；取消检查轻量，进程树和内存按需采样，不将重采样放入热路径。
- 进程 owner 跟踪实际退出，不用父进程退出或代理完成替代所有消费者退出证明。

## 9. 研究与开放设计

研究目标、评价口径、数据权限、预算和停止条件属于约束；首批特征、模型家族、参数接口及实验实现属于可调整选择。实现限制不能悄悄变成选题边界。

每个关键实验说明增加什么信息、什么观察会否定假设。代理指标、输入资格和工程实现通过，与最终目标改善分别报告。

持续负结果或局部解释被反例推翻时，主控汇总跨批次证据，判断剩余未知和下一实验的判别价值，而非继续微调、填满额度或按失败次数机械升档。必要适配在原授权内推进；真正改变科学目标、资源或停止边界时再向用户取得决定。

辅助验证、恢复和框架建设必须服务于用户目标。它们开始主导工作时，主控可撤销自选方案，但保留有效验收标准、用户硬边界和已有数据、进程及资源责任。

## 10. 前端体验与视觉设计模块

### 10.1 定位与设计优先级

`frontend-design` 是按需技能，不是固定设计代理，也不改变模型路由。新建、重设计、美化或显著调整界面时加载；纯后端和没有视觉变化的逻辑修复不加载。

设计优先级依次为：用户指定的设计语言或品牌规范；已有项目局部修改所遵循的设计系统；没有指定方向的新界面或获准重设计所采用的默认编辑式设计。

编辑式设计以字体、网格、尺度对比、留白和细线组织内容，不限定米白、衬线或报纸皮肤。工作台保留紧凑功能区，高密度表格、日志和表单不为装饰牺牲效率。

### 10.2 从内容到代表页面

先确认主要任务、关键操作、必要状态及真实内容长度。方向未定时比较少量有实质差异的参考或代表页面；已有明确方向直接实施，不强制多方案或独立原型。

简要确定视觉重心、字体角色、色彩角色、空间密度、组件材质和有意义的识别特征。用代表页面验证，再扩展其他页面，不以“高级、现代”等抽象形容代替设计选择。

信息取舍遵循以下约束：

- 删除无独立作用的标语、欢迎语、同义副标题、装饰性眉题和重复辅助段落。
- 同一视图中的同一事实原则上只出现一次；次要元数据按任务需要放入详情，不默认全部展开。
- 主界面优先呈现对象、关键状态和主要操作；移除冗余后重新组织布局，不留空容器或靠缩小字号掩盖密度。
- 保留字段标签、必要状态、风险、错误恢复、单位和无障碍名称；理解主流程所需信息不能藏进 tooltip。

中文排版核对长标题换行、标点、行高、中英混排、数字对齐及字体回退。离线页面不暗中依赖网络字体；字体资源同时考虑可获取性、许可与体积。

### 10.3 可选预览与真实视觉闭环

非 HTML 目标可先用隔离 HTML 确认布局、字体、色彩与密度，但不强制第二套界面或转用 WebView。TUI 优先真实字符网格，复杂原生交互优先目标框架小样。

用户要求“先展示，确认后修改”时，只制作隔离预览，不改目标生产界面；未要求时不额外建立审批。预览标明演示数据与模拟行为，视觉方向确认不扩展功能、数据或部署权限。

正式实现回到目标技术栈与设备，核对真实字体渲染、缩放、安全区域、输入方式及关键动线。Web 查看宽窄屏真实截图并操作关键状态，检查焦点、对比度、触控与溢出。DOM、构建和截图各有作用，不能相互替代全部验收。

显著重设计可安排独立视觉审查，复用已有角色与有效截图。审查区分功能或无障碍缺陷、偏离选定方向与可选审美建议，不虚构美学分数，也不因新偏好无限打磨。
