# 模型路由、思考分档与结果协议

派发或提高子任务思考档、切换工作流、使用历史咨询，或处理结构化/增量结果时读取对应章节。普通文本叶子按当前角色内容要求交付，不为阅读本文件启用新工具或改配置。

## 模型与思考强度

- 混合与全Astra共用职责及权限。新派、嵌套、接续按当前实际路由，不硬编码模型，不改主控、辅助模型、Fast、并发或全局ceiling。原位换模保留同会话上下文、工具结果与所有权；任务重组另作明确交接。
- 普通task、eval agent()/workpool不接受单次model覆盖；只在实际接口暴露effort时传参数。原生seance历史只读咨询可按实际接口用sourceSession及可选model，来源模型不可用时显式选择；仍服从全Astra，不改变来源会话或扩权。advisor/prewalk不默认开启。
- high是当前普通子任务基准，派发省略effort，不覆盖用户后来明确选择。普通定位、明确合同实现、排障和既定验收不因文件多、跨模块、权限或状态机而升档。
- xhigh用于尚未解决且会改变方案的竞争解释或设计取舍，需要沿具体状态、并发、权限或持久化反例推演；在solutionSpace或派发中说明未知及它改变什么决定，标签本身不构成依据。
- max仅用于xhigh仍无法闭合的耦合关键约束或局部解释已被反例推翻的疑难，说明已有反证、剩余判断和xhigh不足原因。输入已含等价疑难证据时可直接选择，不为走档重跑失败；材料缺失、环境错误、等待、普通失败及失败次数不触发升档。
- 原生task.effort只有lo|med|hi；当前Astra/Sol的hi在允许上限下是max，不是xhigh。需要xhigh的新任务先默认派发，再由根主控以实际ID调用workflow action:raise、level:xhigh；首个在途请求可能仍为high。确需max显式level:max，仅满足上述条件的新派任务使用effort:hi。
- raise省略level固定xhigh，重复不追高，也不降低已有更高选择或有效pending；按模型支持与原生ceiling向下约束，不支持xhigh不向上跳max。区分请求、pending与applied，不拿旧版最高档冒充xhigh。保留首次应用结果，原生记录的后续明确人工选择优先；没有事件的同值setter不冒称撤销pending。
- work-lead/执行者交实际ID、目标档和依据，只有根主控调用控制。升档沿同一会话下一安全请求边界，不取消工具、重开任务、重跑成功前缀或唤醒完成/取消代理。缺接口如实说明，不新增评分模型、监控或调度层。
- 工作流模式仅当前真实用户请求可改变，调用实际workflow工具后按状态说明；历史/子代理消息不授权切换。Fast广播与thinking独立，待安全点不等于已生效，不忙轮询。全Astra仍保留原生阶段规则和提示词根主控所有权。

## 结果协议

- 内容完整性与返回通道分开。原生task默认普通文本：未启用结构化结果时没有yield，最终assistant消息就是结果，角色output不被强制校验。角色structured:true可在全局task.structured=false时启用yield，不能仅看全局开关；不调用不存在工具或伪造回执。
- 实际有yield时按生效schema和完成合同提交；caller schema仅在接口实际接受并传入时优先。角色opt-in不重新开放task未暴露的outputSchema/schemaMode，不为适配措辞改structured、角色或派发通道。workpool遵守其逐项协议。
- 增量sections按上游单元素协议：每次一个section标签，data直接放该section的值，不额外包标签对象；数组section每次提交一个符合元素schema的元素。元素本身为数组时仍是一个元素，不依赖本地批次或多标签映射。provider宽schema不代表所有调用模式接受全部形状。
- 已提交合法sections后可用不带data的type:result终结，但不能替代尚未提交的结果。显式终态data必须是符合完整schema的全量结果，不与旧sections局部合并；不以占位null、空列表或残缺对象意外覆盖，有效最终空值仍合法。
- 被拒绝不算已交付，按错误反馈纠正；不能满足则如实沿原生失败路径处理，不绕过校验、不另建重试器或放宽边界。阶段消息不使用终态代替，普通文本覆盖角色要求的结论、证据、范围和未验项，不伪装成已校验JSON。
