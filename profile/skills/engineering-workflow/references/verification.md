# 验证、审查与证据复用

在选择/编写测试或runner、安排验收、审查改动或判断发布证据前读取。检查的是本次实际消费者和风险，不默认加载全仓测试矩阵。

## 验证选择

- 先判断当前变化影响的必要行为、已有证据和剩余缺口，据此选择有效验证；把辅助验收设为前置时，说明它阻断哪项交付及现有证据为何不足，不新增审批表或评分报告。必要行为必须运行观察，已有真实流程足够就不另起等价烟测；更换owner、进入新阶段或交付本身不构成重测理由。
- 输入未变且覆盖成立的成功证据随交接复用；只补受变更、失败或具体缺口影响的段落。命令退出0、测试名称/数量、schema通过或代理摘要不等于消费者覆盖；核实际命令是否跑到选定范围，不把意外全套通过当预定结果。
- 跨生产者/消费者变化，沿关键值、身份或版本核对真实读取、状态准入、封存与最终消费。包括本次接口允许的合法空值/稀疏表示、历史输入与直接调用方；不为每次改动穷举所有入口。已有失败指向共同接缝时先用最小反例查共同根因，避免完整启动后逐个撞同类遗漏。
- 历史工件按原执行身份和封存事实验证，新执行的权限、owner、取消、代际和额度按当前控制状态验证。区分源码/运行根与业务数据根；不得用历史可读性替代现场控制资格，也不让可变当前状态否定合法历史。不递归重证已核不可变子图，不缓存整份执行许可。
- 昂贵运行前，以已知规模核单位、输入/输出基数、同时驻留生命周期和最终消费者容量；小样本不能代替已知全量边界。工件需要跨退出/清理/重开时核持久归属及随后真实读取；跨进程准入验证真正使用凭据/工件的后续消费者，不只生成端。

## 永久测试与失败处理

- 长期测试保护消费者行为、真实回归及关键边界，能指出具体什么错误会让它失败。不测试源码镜像、算法副本、mock回显或无语义的内部调用次数；机械转发不单测，承载鉴权、取消、路由等语义则测该合同。归一化/序列化后等价且未进入不同消费者或状态的参数，不算新增覆盖。
- 复用/扩展已有同路径保护，保留独有有效断言，不为普通接合搭长期子进程框架或逐项破坏性证明测试价值。临时真实消费者足以验证的接合可用临时脚本；不以可逆/小改为由跳过真实风险。
- 用户已报告的失败作为事实，不重跑只为确认真伪。失败先判断被违反的要求是否有效；有权限owner修正或删除依赖死接口、固定实现细节和错误合同的测试，不恢复死代码、吞错、补零、弱化有效标准或增加无依据重试来跑绿。只读验收者交回证据，不自行改生产或永久断言。

## 验收与发布

- 验收输入只要求本次运行读取的实现、runner与依赖稳定，不等全工程完成。运行期间不改依赖；需修复先收口受影响进程，之后仅补受影响证据。官方task阶段限制照常遵守，不能以角色改名规避。
- 证据须对应声称的入口、部署方式、状态和消费者。显式注入、手工装配、helper或合成SSE只证明经过的路径，不外推默认发现、正式启动、live provider或模型遵从。缺口不影响交付则收窄结论，影响则补最小验证，不再全量审计。
- 独立验收负责判断现有证据与补缺口，不以亲自重跑才算独立。共用UI/协议行为能推翻同一产物时，相关结果到齐后才打包/发布，无关分片继续。临时runner的必要修正同步实际交付验收入口，私有脚本通过不能冒充正式入口可用。
- 最终核完成项、接口/关键不变量、实际命令与环境、结果/失败及未验项、资源状态；保留必要原始失败和证据位置。启动、局部就绪、一次失败或审批节点不结束用户目标，继续授权内修复/接续，真实阻塞则交具体边界及已完成的可达工作。
- 更新实际受影响的现有说明，最后消费者结束后清理临时工具；不为每片另造报告平台。模型/工作流对照获准时保留最小去敏版本、起止、请求数、input/output/cacheRead、缺失usage和退出/超时，不保留凭据。全目标满足且证据充分即停止。

## 定向审查

- 只审指定变化和必要接缝，缺陷给位置、触发条件、违反合同、后果与证据；无发现可以正常交付。风格偏好、假想兼容、防御性增强或未新增测试不自动成为缺陷，不以审查扩大目标。
- findings与coverage/unverified都要实质读取；区分已证缺陷、具体未解决缺口与可选建议。correct表示指定范围无成立缺陷，不是全局验收开关。复核原问题及直接影响，不重开全面审计。
