# 前端体验与视觉设计

在设计或显著修改网站、应用页面、组件的视觉与交互时使用；纯后端、无视觉变化的逻辑修复不加载。本技能补充公共工程合同，不另建编排、模型路由或审批流程。已读正文在当前上下文复用。

## 设计方向与优先级

1. 用户本次指定的设计语言、品牌规范和参考优先；指定工业、极简、复古、玻璃质感等方向时，按该方向重新选择构图、字体、色彩、材质与动效，不能只换强调色而保留编辑式外壳。混合语言须说明各自适用区域，避免无依据拼贴。
2. 对已有项目的局部修改，延续其明确的设计系统及平台惯例。默认风格不授权全站换肤、替换文案或修改无关功能；用户要求重设计时才在获准范围替换旧视觉。
3. 新界面或获准重设计、又没有指定其他方向时，默认采用 **Editorial Design（编辑式设计）**：以字体、网格、尺度对比、留白和细线组织内容，形成完整页面构图。它是一种组织语言，不等于固定米白配色、衬线字体或报纸皮肤。

先识别页面的主要任务：阅读、操作、展示还是转化。工作台采用编辑式概览与紧凑功能区；高密度表格、日志、表单保留效率和熟悉的控件，不为构图牺牲可发现性。风格不能凌驾于内容、功能、无障碍与平台约束。

## 从产品事实到视觉方向

- 读取本次涉及的页面、组件、样式及真实内容，确认用户主要目标、关键操作和必要状态。重设计保留原能力、权限、错误恢复与关键动线。能力图、状态图和动线图只在能澄清本次复杂关系时使用，不为小改扫描全仓或强制三图齐全；缺少使用频率证据时标明假设，不编造用户行为。
- 已有明确方向直接实施；方向尚未确定、不同构图会改变体验时，用少量有实质差异的参考或代表页面比较。说明借鉴参考的具体内容，如标题比例、分栏节奏、摄影处理，不照搬品牌、整页或受限资产。没有参考材料时可自主制定方向，不因等素材阻塞可完成工作。
- 在现有任务说明或设计记录中简要确定：页面用途、主要视觉重心、字体角色、色彩角色、空间/密度、组件材质及一个有意义的识别特征。拒绝只写“高级、现代、有质感”。不为每次任务创建额外文档体系，不以方案数量或新奇程度作为成绩。
- 用代表页面验证设计语言，再扩展到其他页面；可直接在真实技术栈中实现，不强制先造独立原型。使用真实或有代表性的内容长度与数据密度；展示数据明确标注，不伪造业务收益、客户背书、实时服务或可用功能。

## 跨技术栈的可选设计预览

- 非HTML目标也可用独立HTML预览构图、字体层级、色彩与密度，适用于新界面、整体重设计、风格未定或正式修改成本较高的任务。小改、成熟设计系统或目标框架已有便捷预览时，直接使用目标实现，不默认制作第二套界面。
- 先识别目标平台与主要限制。Web技术桌面界面可复用相同组件；Qt/WPF/Avalonia等原生桌面、Android/iOS与自绘界面的HTML仅为视觉/有限交互原型，提前考虑可用字体、控件形态、尺寸和输入方式。不要用目标平台无法落地的效果争取确认。TUI优先真实字符网格预览，复杂运动与平台交互优先目标框架小样。
- 用户明确要求“先展示、确认后修改”时，只制作隔离预览，不改目标生产界面；交付预览与待确认的关键选择后等待确认。未要求该边界时，按授权自主推进，不把可选预览升级为固定审批。不因确认视觉稿擅自扩展功能、数据或部署权限。
- 预览应覆盖代表页面和会影响判断的关键状态，标明演示数据及模拟交互，不冒充原生行为。交接选定的布局、token、字体角色、密度、状态与响应式规则；HTML代码是否复用由目标技术栈决定，不强制转用WebView。
- 确认视觉方向不等于成品验收。正式实现须回到目标框架和实际设备/窗口，检查字体渲染、缩放、安全区域、键盘/手势、可访问性及关键动线；HTML截图不证明原生交互或性能。Android实际开发和设备操作另按需加载已安装且适配本机的设备技能；本分享包不附带设备技能，缺少时先明确工具与权限，不猜测设备入口。

## 默认编辑式语言

### 构图与节奏

- 页面应有明确的首要内容和阅读顺序。用主次尺度、位置、对齐与对比形成视觉重心，避免所有模块同样大小、同样醒目；操作型页面不必有巨幅Hero。
- 采用可解释的网格与共享对齐线；可用非对称主辅栏，但不固定要求12栏。窄屏按内容优先级重排，不能只把宽屏等比例缩小。
- 让内容群内部紧凑、群之间有间隔、主要分区有呼吸。留白服务于阅读与分组，不以浪费首屏或额外滚动制造“高级感”。
- 优先用位置、排版、留白和分割线组织内容；只有确需独立操作、分组或层级的区域才使用卡片。圆角、阴影、渐变与纹理按功能和方向选择，不做全局禁令，也不让装饰代替结构。

### 字体与中文

- 为展示标题、正文、工具标签与数字分配清晰角色，形成克制的字号和字重阶梯。编辑式不强制衬线：理性工具可用有力度的无衬线标题，阅读型内容可采用适配中文的衬线。
- 明确中文、拉丁文与等宽数字的字体回退；使用可获取且授权允许的字体，不能依赖用户未安装的字体才成立。离线交付不偷偷依赖网络字体；需要嵌入字体时考虑体积与许可。
- 检查中文长标题换行、标点、行高、中英文混排及数字对齐。正文保持舒适字号和对比度，不用极小、浅灰说明制造精致感，不对中文正文套用英文大字距或全大写规则。
- 序号、栏目名与英文眉题应携带真实信息，不为杂志感重复中英文标题、堆装饰编号或口号。编辑式设计靠构图与排版成立，不靠增加“栏目感”文字。

### 信息取舍

- 默认不添加标语、欢迎语、同义副标题、装饰性眉题或解释界面用途的辅助段落。每段可见文字须提供当前判断或操作需要的独立信息；布局、标题和控件已经表达清楚的内容不再复述。
- 同一视图内的同一事实原则上只呈现一次；避免摘要、统计卡、筛选计数、列表和脚注反复报同一状态或数量。确有不同操作上下文才重复，不为填满版面增加标签。
- 主界面优先呈现对象、关键状态与主要操作；方法、编号、更新时间、观察范围等次要元数据按任务需要留在详情，不能默认全部展开。移走重复区块后重新组织布局，不保留空容器，不以缩小字号或降低对比度掩盖冗杂。
- 辅助说明只用于解除具体歧义、说明必要后果或提供错误/空态恢复路径；状态变化通过相应控件与状态位置反馈，不再叠加解释同一变化的长段落。演示声明集中一处，除非脱离上下文展示会造成实质误导。
- 保留字段标签、必要状态、风险和错误说明、单位以及无障碍名称；不得把理解主流程所需的信息藏进tooltip。交付前检查删除某段文字是否影响理解或操作，不影响则删除，不把信息密度等同于文字数量。

### 色彩、材质与运动

- 建立表面、正文、次要文字、边界、强调和状态色的角色，用少量token统一管理。默认可采用纸感浅底、墨色正文与克制强调色；产品内容、主题或明确品牌需要时可采用冷白、深色或其他配色。
- 强调色集中到主要行动、当前选择或关键内容；成功、告警、错误具有一致语义，并辅以文字或图形，不能只靠颜色表达状态。
- 控件在hover、focus、active、disabled等状态下仍清晰可识别。动效解释展开、切换或状态变化，支持reduced-motion，不自动加入循环动画、视差、噪点或发光。
- 视觉资产有实质作用时才采用。图像生成图或静态稿只能辅助方向选择，不能替代真实界面的实现、截图与交互验收。

## 实现与视觉闭环

1. 复用现有组件与技术约定，将已选方向落实为必要的样式token和布局规则，避免为了换风格重写无关业务。只交付已实现的控件；没有业务后端的展示页清楚说明演示范围，按钮应完成对应本地交互或明确不可用。
2. 在真实浏览器运行页面，观察代表性宽屏和窄屏。检查实际构图、阅读顺序、中文排版、密度、溢出、关键状态与交互；结合键盘焦点、对比度、表单标签和触控操作检查可用性。截图供视觉判断，DOM、构建和自动检查不能替代看图；静态截图也不能证明动态操作正确。
3. 对发现的问题给出具体位置、偏差、影响与修正方向，例如“统计区与当前任务同等醒目，主操作失去优先级”，不使用“还不够高级”作为返工要求。修复影响交付的问题后补验相应路径，不因主观新偏好无限打磨。
4. 新页面或显著重设计可安排独立视觉评审；复用现有角色和有效截图，不要求每个小改都新增代理。评审依据用户方向、产品任务与实际画面，区分功能/无障碍缺陷、偏离已选方向和可选审美建议，不虚构客观美学分数。主控负责最终取舍，用户对“对不对味”的反馈优先于代理自评。

无可用浏览器时交代限制，不能宣称视觉验收完成。交付说明完成内容、可打开入口、实际观察到的行为与影响结论的未验项；风格选择与工程正确性分别判断。

## 与工程工作流的接合

主控负责本技能提示词与关键设计取舍；官方task承担边界明确的非提示词设计实现，verifier负责稳定输入的真实运行与截图，必要时使用独立审查上下文。遵守原角色权限，不用本技能解除阶段限制或转派限制。混合与全Astra使用同一技能，模型、思考档位、Fast与并发沿现有工作流，不因视觉任务自动升档或新增固定角色。
